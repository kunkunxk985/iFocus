# iFocus Project Rules

Hermes: when working in this repo, follow these rules.

## Project Info
- Language: Swift (tools-version 5.8+, macOS 13+)
- Platform: macOS 13+
- Build system: Swift Package Manager
- App version: **1.6.2** / build **62** (see `Scripts/package_app.sh` + `AppVersion`)
- Entry point: `Sources/iFocus/iFocusApp.swift`
- Main stores: `TimerStore.swift`, `TaskStore.swift`, `SettingsStore.swift`
- Settings UI: **only** `SettingsWindowView` (window id `settings`); do not reintroduce embedded `SettingsView`

## Build & Verify
- Build: `swift build --disable-sandbox` from project root
- Tests: `swift test --disable-sandbox`
- Package: `bash Scripts/package_app.sh` → `Build/iFocus.app`
- Smoke: `bash Scripts/smoke_test.sh`

## Style
- Use SwiftUI with AppKit interop where needed
- Keep Store classes as `ObservableObject` with `@Published`
- Views are fileprivate components; keep modifiers chain-readable
- Localization: current strings are Chinese; preserve existing tone
- No force unwrap in new code without comment explaining why
- Delete tasks by `id` / `FocusTask`, never by filtered-list index

## Harness Engineering

Apply three-layer discipline to all non-trivial changes:

### Layer 1: Security
- Do not delete `tasks.json` or `focus_sessions.json` from `~/Library/Application Support/iFocus/`
- Do not modify `Package.swift` platforms without user confirmation
- Do not add network calls, analytics, or telemetry without explicit request

### Layer 2: Perception
Before editing, read the relevant Store and View files.
Check `git status` if repo becomes a git repo later.
Note which filter mode (`todayTask`, `tomorrowTask`, etc.) the View targets.

### Layer 3: Review
After changes:
- Confirm SwiftUI preview mentally: bindings, state ownership, environment objects
- Verify timer state transitions: start -> pause -> reset -> complete
- Check task persistence paths under `Application Support/iFocus/`
- Ensure no user-facing strings changed unintentionally
- Re-run `swift build` and `swift test`
